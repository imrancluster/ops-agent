# M00: Engineering Foundations (my notes)

**One-line summary:** before writing any agent code, make the project *safe to change*.
That means git, one command that answers "is the code healthy?", strict linting, and CI that checks every push.

---

## The learning path (what I did, in order)

### 1. Version control (Task 1)
- `git init` → `.gitignore` → **check secrets are ignored before the first commit**:
  `git check-ignore -v .env`
- A secret that gets committed stays in git history forever. Removing it later doesn't help; you have to rotate the key.
- `go.sum` **is** committed: it locks the exact dependency hashes (supply-chain safety).
- Git tracks files, not folders. Empty folders don't show up.
- `.editorconfig`: LF line endings + tabs for Go, so Mac and Windows produce the same files.

### 2. Toolchain (Task 2)
- Go analysis tools (golangci-lint, gopls, govulncheck) contain their **own copy** of the Go parser.
- **Rule:** the tool must be *built with* Go ≥ the version in `go.mod`, or it refuses to run or gives wrong answers.
- Check it: `go version -m "$(which gopls)"`
- After every Go minor upgrade (1.27 → 1.28), rebuild the tools:
  `go install golang.org/x/tools/gopls@latest` (same for govulncheck).
- Patch versions (1.27.2 vs 1.27.4) are the same language, so they're fine.

### 3. Makefile + linters (Task 3)
- `make help` lists all commands. **`make check` before every commit** (fmt + vet + lint + test).
  Running only `golangci-lint run` is not enough, because it skips formatting, vet and tests.
- Every package has a `doc.go` explaining its job and its dependency rules.
- Every exported name needs a doc comment that starts with its name:
  `// Fetch returns the HTTP status code for rawURL.` (not "Fetch is a function to...").
- **Linters catch mechanical mistakes; review catches design mistakes.** My playground was
  lint-clean but still dropped errors and hard-coded its HTTP client.

### 4. CI (Task 4)
- GitHub Actions runs the *same* `make check` on every push and PR. A green laptop should mean a green CI.
- `permissions: contents: read` = least privilege (the same idea as the agent's read-only DB).
- Tool versions are pinned (`golangci-lint v2.15.0`), so CI never breaks by surprise.
- `timeout-minutes` = a hard limit, like `MaxSteps` in an agent.

### 5. ADRs (Task 5)
- An ADR records **why** we decided something: context, options (each with the reason it lost),
  decision, consequences, and a **measurable "revisit when"** signal.
- Never rewrite an accepted ADR. Write a new one that supersedes it.
- A reversible decision is a cheap decision: keep vendor code behind one interface.
- My decisions so far: 0001 raw `net/http` + `encoding/json/v2` (stable in Go 1.27), 0002 local Ollama by default.
- `.env.example` (fake values) is committed; `.env` (real keys) never is.

### 6. Lab: the agent loop by hand (Task 6)
I played the role of the agent with `curl`. One full turn of the loop:

```
user question ──► model: "please run get_current_time" (content is empty!)
              ──► I run the tool myself
              ──► I send back: question + model's tool request + tool result
              ──► model answers with my data
```

- **The model knows about tools (from their descriptions), but only my code runs them.**
  When it wants a tool, its whole reply is the request, so `content` is empty.
- **Stateless:** the model remembers nothing. "Memory" = my code re-sends the full history every call.
- **The three messages of a tool turn:** `user` (the question), `assistant` + `tool_calls`
  (proof the model asked), `tool` (the result). The model needs all three, every time.
- **Lenient vs strict APIs:** Ollama accepted a tool result *without* the assistant's request;
  Claude rejects it with HTTP 400. **Write for the strictest API**, or switching providers breaks things.
- **Tool output = source of truth.** The model cannot verify it. I gave it a fake time and it believed me.
  Good for grounding, dangerous for bugs and prompt injection (M08).
- `think: false` skips qwen3's hidden reasoning, so there are fewer output tokens and faster simple steps.

**Ollama facts for M01** (checked on Ollama 0.40.15, these differ from the guide):

| Fact | Consequence |
| --- | --- |
| Tool calls include an `id` | use it if present, generate one only if missing |
| `done_reason` is `"stop"` even for tool calls | detect tool use by `len(tool_calls) > 0`, not `done_reason` |
| `arguments` is a JSON object | OpenAI sends a *string*; different in M05 |
| Durations are in nanoseconds | `load_duration` ≈ 7 s on the first (cold) call |
| Tokens: `prompt_eval_count` = input, `eval_count` = output (thinking included) | that's what costs money on paid APIs |

## Linters cheat sheet (what each one protects me from)

| Linter | Catches | Why it matters in an agent |
| --- | --- | --- |
| **errcheck** | ignored errors | a failed tool looks like success, so the model gets wrong data |
| **govet** | suspicious code (bad `Printf` args, copied locks, ...) | subtle bugs the compiler allows |
| **ineffassign** | values assigned but never used | usually a forgotten `if err != nil` |
| **staticcheck** | bugs, deprecated APIs, simplifications | the "senior reviewer" linter |
| **unused** | dead code | less code = less to secure |
| **bodyclose** | HTTP response body not closed | leaks connections to the LLM API |
| **noctx** | HTTP request without a context | an LLM call that can never time out or be cancelled |
| **contextcheck** | creating a fresh ctx instead of passing one on | user cancel / timeout gets lost halfway down |
| **errorlint** | `err == ErrX`, missing `%w` | breaks once errors are wrapped; retry logic fails |
| **gosec** | security: SQL injection, unsafe URLs, `0666` file perms | the model's input is untrusted, like a user's |
| **revive** | style + missing doc comments | readable code for the next person (future me) |
| **sloglint** | inconsistent `slog` logging | agent logs must be machine-searchable |
| **misspell** | typos in comments/strings | professionalism (only checks Go files) |
| **nilerr** | returning `nil` after checking an error | silently swallowing a failure |
| **unconvert** | unnecessary type conversions | noise that hides real logic |

## Error-handling rules I learned from the playground review

1. **If you have an error, wrap it with `%w`.** Never drop it:
   `fmt.Errorf("parse url %q: %w", rawURL, err)`
2. **Add context at every layer**, so a log says *what* failed, not just `connection refused`.
3. Compare errors with `errors.Is` / `errors.As`, never `==`.
4. Use `%q` for user input in messages, so empty strings and whitespace stay visible.
5. Never use `http.Get` / the default client: it has **no timeout**. Use `NewRequestWithContext` + a client with a `Timeout`.
6. **Inject dependencies** (pass the `*http.Client` in) instead of creating them inside the function, so tests can swap in `httptest`.
7. Files the agent writes: `0600`, not `0666`.

## Commands to remember

```bash
make check                 # before every commit
make fmt                   # auto-format
git check-ignore -v .env   # is my secret safe?
go version -m "$(which gopls)"   # which Go built this tool?
gh run watch               # watch CI live
```

## Commit message format (Conventional Commits)
`type(scope): imperative summary`, for example `feat(llm): add Ollama adapter`, `docs(notes): ...`, `ci: ...`, `chore: ...`
Imperative mood: "add", not "added" (read it as: "this commit will *add*...").
